Заказ блюд

Веб-приложение интернет-столовой. Пользователь заходит, смотрит меню, кладёт блюда
в корзину и оплачивает заказ деньгами с внутреннего кошелька. Модератор и админ
могут добавлять блюда, менять цену и удалять их, а админ ещё и смотреть список
пользователей и выдавать роли.

Стек

Java 17, Spring Boot 3.4, Spring MVC, Thymeleaf, Spring Data JPA, PostgreSQL,
Spring Security, Spring Cache с Redis, ModelMapper, Lombok, Bean Validation,
Actuator, Maven.

Архитектура

Три слоя: контроллеры, сервисы, репозитории. Сервисы разбиты на интерфейс и
реализацию. Сущности базы наружу не отдаются, везде ходят DTO, которые
маппятся из сущностей через ModelMapper. Страницы рисуются на сервере
шаблонами Thymeleaf, отдельного REST API здесь нет.

По пакетам: controllers, services и services.impl, repositories, models.entities,
dto, configuration, templates с шаблонами. Ещё есть класс Init, который при старте
приложения создаёт демо-категории, блюда и пользователей, чтобы было что посмотреть.

Модель данных

Пользователь, роль, категория, блюдо, корзина, позиция корзины, заказ и позиция
заказа. Корзина привязана к пользователю, блюдо к категории. Заказ связан с
блюдами через промежуточную таблицу, и в ней отдельно сохраняется цена на момент
оформления. Это сделано для того, чтобы изменение цены в меню не переписывало
уже сделанные заказы.

Что интересно по коду

Безопасность. Своя таблица пользователей и свой UserDetailsService, пароли
хранятся в bcrypt. Доступ разграничен по url: меню и корзина доступны
авторизованному, добавление и удаление блюд только модератору и админу,
список пользователей только админу. Для отказа в доступе своя страница.

Кэширование. Redis подключён как провайдер Spring Cache, на сервисах стоят
аннотации Cacheable и CacheEvict. Кэшируются блюда, пользователи и категории,
при изменении данных кэш сбрасывается. Серилизация в json, настроен ObjectMapper,
чтобы нормально работали даты, и задано время жизни записи.

Валидация. На DTO висят аннотации ограничений, в контроллерах разбирается
BindingResult, ошибки возвращаются обратно в форму. После успешных действий
используется приём redirect с flash-атрибутами, чтобы сообщение показывалось
один раз и страница корректно перезагружалась.

JPA. open-in-view выключен, транзакции помечены явно в сервисном слое,
пагинация идёт через Page и Pageable, стратегии подгрузки связей заданы вручную.

Ошибки. Глобальный обработчик на ControllerAdvice плюс отдельные страницы
для 403 и для случая, когда пользователя не удалось найти.

Функции

Меню: список блюд с переключением страниц, сортировкой и поиском, карточка
отдельного блюда и топ-5 по рейтингу внутри категории.
Корзина: добавление и удаление позиции, очистка.
Заказ: оформление из корзины с подсчётом суммы, списанием денег с кошелька
и проверками, что корзина не пуста и денег хватает, плюс список всех заказов.

Как запустить

Нужны PostgreSQL и Redis, параметры подключения лежат в application.properties.
Схема создаётся заново при каждом старте, а тестовые данные подсыпает класс Init.

docker run -d --name postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16
docker run -d --name redis -p 6379:6379 redis:7
./mvnw spring-boot:run

Потом открыть http://localhost:8080
