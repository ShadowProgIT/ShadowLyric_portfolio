AI Helper for Drivers

Веб-приложение-ассистент по ПДД РФ для учеников автошкол. Можно спросить текстом в чате или продиктовать голосом и получить ответ тоже голосом. Ответы строятся на реальной тексте правил, а не на том, что модель запомнила из обучающей выборки.

Состоит из двух сервисов и инфраструктуры вокруг них.

Java-часть (backend, Maven multi-module)

Spring Boot, порт 8080. Два модуля: api-contract с DTO, enums и интерфейсом контроллера, и api-realisation со всей реализацией. Это точка входа для браузера: отдаёт страницу чата на Thymeleaf, принимает сообщения, хранит историю и пересылает всё дальше в Python.

Никакого своего ML здесь нет — Java занимается сессиями, историей, файлами аудио и маршрутизацией. Сессии живут в Redis под ключом session:{id} с TTL 2 часа, история сообщений в Postgres. Раз в сутки в 3:00 планировщик подчищает старое сверх настроенного срока хранения.

Голосовой ввод принимается multipart-загрузкой, файл кладётся в audio_input под случайным UUID, клиент потом опрашивает готовность ответа и забирает wav из audio_output, который проброшен как статика.

Python-часть (python-backend)

FastAPI, порт 8000, один эндпоинт /predict. Сюда Java постит JSON с типом запроса (TEXT или AUDIO), текстом либо именем аудиофайла и выбором модели (LOCAL или GLOBAL).

Дальше два агента. Theory Agent отвечает на вопросы по теории: сначала ищет релевантные фрагменты правил, собирает промпт из контекста, краткого резюме диалога и вопроса, отдаёт модели. Practice Agent рассчитан на вождение: ответ короче (2-3 предложения), с жёсткой обрезкой всего лишнего, потому что он идёт в синтез речи. Если в запросе есть слова вроде аварии, ребёнка или экстренного торможения, агент вообще не дёргает модель, а сразу выдаёт заготовленную безопасную реакцию — тут важна скорость, а не качество генерации.

RAG

Документы ПДД лежат в data/pdd в pdf и txt. При первом запуске они парсятся и режутся по структуре правил: чанкер ищет номера пунктов вида 11.4. и приложения, чтобы не разрывать пункт посередине, и только если структура не узнаётся, падает в обычный рекурсивный сплит. Эмбеддинги делает nomic-embed-text через Ollama, индекс лежит в Chroma в chroma_db.

При поиске берётся вдвое больше кандидатов, чем нужно, после чего идёт дедупликация: фрагменты сравниваются между собой по косинусной близости эмбеддингов, и всё выше 0.92 считается дубликатом. Так в контекст не попадает один и тот же пункт, вытащенный с разных страниц.

Модели

Локально — Qwen, развёрнутая в Ollama из gguf-файла через Modelfile. Там же прописан системный промпт: только русский язык, ссылки на конкретные пункты ПДД и КоАП, никакого вывода процесса размышлений, и явное требование признавать незнание, если контекста не хватает. Альтернатива — GigaChat по API, переключается полем modelType в запросе.

Модель ответов подтягивается через фабрику get_llm, так что агентам всё равно, какая именно LLM за ними стоит.

Безопасность

Отдельный классификатор на TF-IDF и логистической регрессии, обученный на размеченном датасе русскоязычных текстов. Скрипт обучения лежит в приложении, метрики печатаются в лог. Перед обработкой любой текстовый запрос проходит через него: если вероятность вредоносности выше 0.65, модель не вызывается вовсе, пользователь получает один из нескольких заготовленных отказов с переводом разговора на тему ПДД. Если файлы модели нет, классификатор просто отключается и работа продолжается без него.

Память диалога

Полную историю переписки в промпт не тащат. Вместо этого после каждого обмена в фоновой задаче обновляется краткое резюме сессии (2-3 предложения), которое хранится в Redis с суточным TTL и подаётся модели как контекст. Так диалог остаётся связным, а токенов тратится мало.

Голос

Распознавание и синтез — SaluteSpeech API Сбера. Клиент сам получает OAuth-токен по ключу из .env, входящее аудио приводит pydub к 16 кГц, моно, 16 бит, потому что API принимает только такой формат. Ответ синтезируется в wav, имя файла возвращается в Java, та отдаёт его браузеру.

Инфраструктура

docker-compose поднимает Ollama, Redis, Postgres и Python-сервис. Java запускается отдельно, ей нужны только порты снаружи.

Запуск:

docker compose up -d
docker exec -it ollama-server sh
ollama create qwen3.5-driving -f /Modelfile

mvn clean install
mvn spring-boot:run -pl api-realisation
